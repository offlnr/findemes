1. QUÉ ES EL FIREWALL EN ESTA ARQUITECTURA
------------------------------------------
En AWS, el firewall de cada servidor y de la base de datos es su grupo de seguridad: una
lista de reglas que solo deja pasar el tráfico autorizado. Ya estaba definido en el diseño
(ADR-005), pero ningún diagrama lo mostraba como firewall:
  - sg-api (servidor de la API): entrada solo por el puerto 8080 desde API Gateway (VPC Link).
  - sg-admin (servidor de administración): ninguna conexión entrante; se administra por Tailscale.
  - sg-rds (base de datos): entrada solo por el puerto 5432 desde sg-api y sg-admin.


2. DIAGRAMAS ACTUALIZADOS
-------------------------
- Ilustración 27, topología física:
    * Se agregan dos firewalls entre el router de la VPC y las subredes: uno para los
      servidores EC2 y otro para la base de datos.
    * Se corrige el ícono del borde de AWS: antes tenía un ícono de firewall, pero CloudFront
      y API Gateway son el punto de entrada, no un firewall. Ahora es un servidor web, con la
      etiqueta «CloudFront (AWS Shield Standard) y API Gateway».
- Ilustración 28, topología lógica:
    * Cada servidor y la base de datos aparecen dentro de un recuadro rojo de firewall con su
      regla de entrada. La leyenda incluye el nuevo símbolo.
    * Se corrige el Internet Gateway, que decía «Solo tráfico saliente; ninguna regla de
      entrada abierta»: esa restricción la aplican los grupos de seguridad, no el gateway.
- Ilustración 29, diagrama de despliegue:
    * Los grupos de seguridad, que antes eran solo texto dentro de las cajas, ahora son
      límites de firewall visibles alrededor de cada servidor y de la base de datos, con su
      regla. La leyenda incluye el nuevo símbolo.

No se modificaron los diagramas C4 de contexto, contenedores y componentes, los de
componentes UML, los BPMN, los casos de uso ni el modelo de datos: muestran software o
procesos, no la red, así que el firewall no corresponde en ellos.
